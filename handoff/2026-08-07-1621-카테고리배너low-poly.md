# 카테고리 배너 low-poly 배경 인수인계 문서

작성일: 2026-08-07 (KST)

## 1. 목표

`index.html`의 카테고리 배너(`.cat-gold`/`.cat-silver`/`.cat-collectible`, 히어로
슬라이더와 겹치는 이글/버팔로/캥거루 사진 교체 건)를 truney.com 스타일의
low-poly(저폴리곤) 골드/실버 배경으로 개선하는 작업. 지난 4차례 세션에서
"불규칙한 진짜 low-poly"를 만들지 못하고 격자형 반복 패턴만 나왔던 문제를
이번 세션에서 해결함.

## 2. 현재 상태

### (1) low-poly 배경 생성 방식 문제 해결 (확인 완료)

- 기존 시도(preview.html~v4)는 그리드 위에 삼각형을 올리는 방식이라 결국
  타일이 반복되는 패턴이 됨 — 핵심 미해결 문제였음
- 이번엔 Python(numpy+scipy)으로 **불규칙 포인트를 무작위로 흩뿌린 뒤
  Delaunay 삼각분할**로 진짜 비정형 삼각망을 생성하고, 각 꼭짓점에 무작위
  높이값을 부여해 조명 각도(dot product)로 명암을 계산하는 방식으로 전환 →
  구조적으로 반복 패턴이 나올 수 없음
- 코인 실사진(레포의 실제 상품 이미지, 버팔로/브리타니아/브리티시라이온)을
  원형 합성해 이미지 깨짐 여부까지 로컬 렌더링(wkhtmltoimage)으로 사전 확인함
  → 정상 표시 확인
- 사용자가 배경 패턴만 크게 확대해서 보니 "텍스트/버튼이 잘 안 보일 것 같다"는
  가독성 우려 제기 → 코인 합성 없이 배경+텍스트만 쓰는 방향으로 논의 전환

### (2) 텍스트 가독성 확보 방안 — 두 가지 제시, **아직 미결정**

- **A안**: 색상 대비를 압축한 연화(soft) 톤 + 텍스트 중앙에 방사형 스크림
  (은은하지만 원본의 강한 "구겨진 금박지" 임팩트가 줄어듦)
- **B안**: 원본 진한 톤 그대로 유지 + 텍스트/버튼 뒤에 반투명 카드(패널) 배치
  (배경 임팩트는 유지, Claude가 개인적으로 추천했으나 사용자 최종 확답은 아직 없음)
- 절충안(연화 톤 + 카드 병행)도 가능하다고 안내했으나 사용자가 아직 선택 안 함

### (3) 에셋 유실 방지를 위한 레포 저장 (완료, 커밋 `0cfad28`)

- 지난 세션에 프리뷰 파일이 `/mnt/user-data/outputs`(임시 작업공간)에만 있다가
  세션 종료로 유실된 전례가 있어, 톤/가독성 방식이 확정되기 전이라도 먼저
  레포에 저장해둠
- 저장 위치: `assets/images/banners/` (신규 폴더, 루트 `/images`가 아님 — 루트
  `/images`는 용량 문제로 매 세션 sparse-checkout에서 제외하는 폴더라 거기
  새 파일을 추가하면 다음 세션이 놓치기 쉬움)
- 저장된 파일:
  - `gold-lowpoly.svg` / `silver-lowpoly.svg` / `bronze-lowpoly.svg` (원본 진한
    톤, B안에서 사용)
  - `gold-lowpoly-soft.svg` / `silver-lowpoly-soft.svg` / `bronze-lowpoly-soft.svg`
    (대비 압축 연화 톤, A안에서 사용)
  - `README.md` (에셋 설명 + 결정 대기 상태 메모)
- 재생성 스크립트: `scripts/generate-category-banners.py` (numpy+scipy 필요,
  포인트 시드/색상 스톱/조명 방향 조정해서 재생성 가능)
- **아직 `style.css`/`index.html`에는 미반영** — 순수 에셋 저장 단계

## 3. 진행 단계

3. Python(numpy+scipy)으로 불규칙 삼각분할 + 높이맵 기반 명암 스크립트 작성,
   골드/실버/브론즈(컬렉터블용) 3색 SVG 생성
4. 코인 실사진(레포 git 히스토리에서 개별 blob 추출, sparse-checkout 범위
   밖이라도 `git show HEAD:경로`로 추출 가능함을 확인)을 원형 합성한 v5
   프리뷰 제작, wkhtmltoimage로 로컬 렌더링해 이미지 깨짐 없음을 확인 후
   사용자에게 공유
5. 사용자가 스크린샷으로 배경 패턴만 확대해서 보고 텍스트 가독성 우려 제기
   → 코인 없이 배경+텍스트만 사용하는 방향으로 재설계
6. 대비 압축한 soft2 톤 재생성, A안(연화+중앙 스크림)/B안(원본+반투명 카드)
   두 가지 비교 프리뷰(v6) 제작해 공유 → 사용자 최종 선택 대기 중 (중단)
7. 사용자가 "이미지 유실 방지"를 위해 레포 저장을 요청 → SVG 6종 +
   재생성 스크립트 + README를 `assets/images/banners/`, `scripts/`에
   커밋(`0cfad28`)·푸시 완료

## 5. 참고 사항

- **백업 브랜치**: 이번 세션은 생성하지 않음 (신규 파일 추가만 있고 기존 파일
  수정 없는 저위험 변경이라 판단). 가장 최근 백업은
  `backup-2026-08-03-1829`(기준 커밋 `d0821c0`)로 여전히 유효.
- **에셋 저장 위치 판단 근거**: 루트 `/images` 폴더는 세션마다
  `git sparse-checkout set --no-cone '/*' '!/images'`로 제외하고 클론하는
  폴더라, 거기 새 파일을 추가하면 다음 세션이 sparse-checkout 설정을 몰라서
  놓칠 위험이 큼. `assets/` 하위는 매번 정상적으로 체크아웃되므로
  `assets/images/banners/`를 새로 만들어 저장함.
- **sparse-checkout 범위 밖 개별 파일 추출법 (신규 학습)**: `/images`가
  로컬에 체크아웃 안 돼 있어도 `git show HEAD:images/products/2026/buffalo.png
  > 파일경로`로 개별 blob을 추출할 수 있음 (git 히스토리 자체에는 남아있으므로).
  프리뷰 제작 시 실제 코인 사진이 필요할 때 sparse-checkout 설정을 건드리지
  않고도 활용 가능.
- **인수인계 문서와 코드/이미지 파일의 역할 구분**: 사용자가 "인수인계 문서를
  만들면 되는데 왜 폴더를 따로 만들었냐"고 질문함 — 인수인계 문서(`handoff/*.md`)는
  글로 된 맥락 설명이고, `assets/images/banners/`는 실제 코드가 불러다 쓰는
  이미지 파일 자체라 텍스트 문서로 대체 불가능함을 설명함. 지난 세션 이미지
  유실 원인도 "인수인계 문서 부재"가 아니라 "이미지 파일 자체를 레포에 저장
  안 함"이었음 — 향후 유사 질문 대비 참고.
- **A안/B안 비교 시 렌더링 도구 한계**: `wkhtmltoimage`(구형 WebKit 기반)는
  CSS Grid(`grid-template-columns`)를 지원하지 않아 3열 배너가 세로로
  스택되어 렌더링됨. 실제 배포 사이트(모던 브라우저)에서는 문제 없음 — 검증
  도구 자체의 한계이니 다음 세션에서 혼동하지 말 것.
- **PAT 토큰**: 이번 세션 1회 push(카테고리 배너 에셋 저장) 채팅에 붙여넣어
  주신 토큰 사용, push 직후 origin URL을 plain HTTPS로 원복함. 토큰 값은
  응답에 노출하지 않았고 메모리/파일/로그에 저장하지 않음.
