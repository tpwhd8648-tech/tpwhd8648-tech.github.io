## 1. 목표

"왜 원트로이 불리온인가 / 이용 방법" 신뢰 섹션을 about.html → index.html에
이어 세 번째 페이지인 coins.html(상품 목록)에도 확대 배치하는 작업. 배치
과정에서 카드 문구를 단순화했다가 다시 세 페이지 동일하게 통일하는 시행착오가

## 3. 진행 단계

1. 사용자가 "다른 주요 페이지에 넣는 게 좋겠다" → coins.html/contact.html
   두 후보 제시 → coins.html부터 먼저 진행 결정
2. coins.html 구조 확인(SSG_GRID 마커 위치, footer 마운트 위치) →
   `generate-coin-pages.js`의 마커 로직 코드 확인해서 안전성 검증 → 신뢰
   섹션 삽입, 동기화 주석 갱신 (커밋 `96eb4e3`~`a864524`는 이전 세션,
   이번 세션 첫 커밋은 아래 4번)
3. 사용자가 "완전히 똑같이 하기보다 조금 단순화하고 싶다" → 카드 문구
   여러 차례 대화로 조정(회원가입 문구 삭제, 정품 취급 문구 변경 등) → 최종
   확정 문구로 coins.html에 반영, push (커밋 `7ccafc6`)
4. 사용자가 "다른 페이지랑 텍스트가 다른 것 같다"고 재지적 → index.html/
   about.html도 coins.html 문구로 통일, 동기화 주석 3곳 모두 갱신, push
   (커밋 `327c84c`)
5. 사용자가 "문의 페이지 번호에 임시라고 적어야 할 것 같다"고 요청 →
   grep 전수 검색으로 번호 노출 3곳 확인 → contact.html만 누락 확인 →
   수정 후 push (커밋 `d4ed45c`)
6. 사용자가 "구매안내 대신 신뢰섹션 넣는 게 좋겠다"고 제안 → coin-detail.html
   + generate-coin-pages.js의 "구매안내" 탭 구조·내용 확인 → 기존 FAQ/배송
   ·환불 정보 손실 우려 안내, A(완전 교체)/B(정보 이동 후 교체) 선택 요청 →
   사용자가 "일단 두자"고 보류
7. 인수인계 요청 → 이 문서 작성

## 5. 참고 사항

- **텍스트 동기화 구조**: 신뢰 섹션 문구는 이제 index.html / pages/about.html
  / pages/coins.html **세 파일에 완전 동일하게 하드코딩**돼 있음(컴포넌트
  시스템이 없는 순수 정적 HTML이라 불가피). 세 파일 모두 섹션 바로 위에
  "텍스트 동기화 필요" 주석을 남겨뒀고, 이번 세션의 단순화→재통일 시행착오
  이력도 주석에 남겨서 다음 세션이 왜 이런 문구가 됐는지 파악 가능하게 해둠.
  향후 페이지가 더 늘어나면 `assets/js/why-section.js` 같은 공용 스크립트로
  분리하는 리팩터링을 고려할 만함(이전 핸드오프에서도 언급된 사항, 아직
  미결정).
- **coins.html 신뢰 섹션의 안전성**: `generate-coin-pages.js`는
  `SSG_GRID_START`/`SSG_GRID_END` 마커 사이만 재생성하고, 신뢰 섹션은 그
  마커 밖(그리드 `</section>` 다음, footer 이전)에 위치하므로 야간 자동
  커밋으로 인해 삭제되거나 덮어써질 위험 없음 — 코드 직접 확인함.
- **전화번호 "(임시)" 표기 3곳**: `assets/js/footer.js`(63행, 104행),
  `pages/contact.html`(144행). 정식 번호 확정 시 이 3곳 모두 동시에 수정
  필요.
- **"구매안내" 탭 구조 파악 완료**: `coin-detail.html`의 322~429행에
  `guideTabHTML` 변수로 하드코딩돼 있고, `scripts/generate-coin-pages.js`의
  451~558행에 거의 동일한 내용이 정적 생성용으로 별도 하드코딩돼 있음(두
  곳이 서로 다른 소스라 향후 수정 시 양쪽 다 고쳐야 함 — 아직 실제 수정은
  안 했으므로 다음 세션에서 결정 후 반영 시 이 두 위치를 기억할 것).
- **백업 브랜치**: 이번 세션 생성하지 않음 — 텍스트 추가/수정 위주라
