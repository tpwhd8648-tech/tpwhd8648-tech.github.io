## 2. 현재 상태

- `scripts/inject-cache-busting.js` 재실행 → 0개 파일 갱신 (배포된 해시가
  현재 파일 내용과 완전히 일치, 멱등성 재확인)

  1:1 정확히 일치 (끊어진 링크 없음)
- `node --check`, `python3 yaml.safe_load` 재통과
- git 히스토리(`bf46957` → `911552f` 자동 커밋) diff 직접 확인 → 봇 커밋은
  `price`/`data-premium` 값만 변경, cache-busting 해시는 건드리지 않음 —
  이전 핸드오프의 "실배포 환경에서 정상 작동" 주장과 일치
- **결론: 오류 없음.** 낮은 우선순위 참고사항 1건만 발견(아래 5번 참고)

### (2) pages/coins.html premium 실시간 갱신 확인 (확인 완료 — 사용자 브라우저 실사용 검증)

- Claude는 컨테이너 네트워크 제약(허용 도메인 목록에 배포 사이트·
  docs.google.com 미포함)과 `web_fetch`의 "사전 검색/fetch 결과에 있는
  URL만 접근 가능" 제약으로 인해 직접적인 콘솔/Network 탭 확인 불가
- 대안으로 사용자가 태블릿에서 실사용 검증 수행: 동일 상품을
  `pages/coins.html`(목록페이지, SSG+실시간 premium 갱신)과 상세페이지
  (`coin-detail.html`, 항상 시트 직접 fetch)에서 각각 표시 가격을 비교
- **결과: 가격 일치 확인** — 목록페이지의 `refreshPremiumsFromSheet()`가
  실제로 최신 premium 값을 정상 반영하고 있음을 간접적으로 실증
  (갱신이 실패했다면 목록페이지만 옛날 값으로 어긋났을 것)
- 콘솔 에러 유무, gviz fetch 상태코드 자체는 직접 보지 못했으나, 최종
  결과값 일치로 실질적 검증 목적은 달성됐다고 판단

## 5. 참고 사항

- **PAT 토큰**: 이번 세션에서 사용자가 채팅에 붙여넣은 PAT는 push 용도로만
  사용하고 응답에 노출하지 않았으며 메모리/파일/로그에 저장하지 않음.
  (참고: 채팅창에 토큰을 붙여넣으면 대화 기록에 평문으로 남으므로, 가능하면
  매 세션 새로 발급하거나 만료 기한을 짧게 유지하는 것을 권장 — 이번 세션
  1회만 안내)
- **Claude의 브라우저 실사용 검증 한계**: 컨테이너 네트워크 허용 도메인
  목록에 배포 사이트(github.io)와 docs.google.com이 없고, `web_fetch`는
  사전에 검색/fetch 결과에 나타난 URL만 접근 가능한 제약이 있어 콘솔
  로그·Network 탭·실제 렌더링 확인이 불가능함. 앞으로 "브라우저 실사용
  확인" 류 To-Do는 이 한계를 감안해 처음부터 사용자 액션(👤)으로 표시할 것
  (이미 그렇게 하고 있었음, 계속 유지).
- **cache-busting 관련 낮은 우선순위 메모**: 파일명 매칭 정규식
  (`scripts/inject-cache-busting.js`)이 `[a-zA-Z0-9_-]+`만 허용. 현재 모든
  에셋 파일명이 이 범위 안이라 문제 없으나, 나중에 `.min.js`처럼 점이
  포함된 파일명이나 한글 파일명을 추가하면 매칭 실패 가능. 지금 당장
  손댈 필요는 없음([영향 낮음]).
- **태블릿 환경에서의 개발자도구 접근성 관련 메모**: iOS는 Mac의 Web
  Inspector, Android는 PC Chrome의 `chrome://inspect` 원격 디버깅이
  없으면 콘솔/Network 탭 확인이 사실상 불가능함. 향후 이런 검증이 필요한
  To-Do는 "목록페이지 vs 상세페이지 최종 표시값 비교"처럼 개발자도구 없이도
  결과로 간접 검증 가능한 방법을 우선 제안할 것.
