## 1. 목표

직전 핸드오프(`2026-09-04-1656`, 커밋 로그 기반 사후 작성)에서 "미확인"으로 남겨뒀던
"배포된 이미지에서 실제로 테두리가 삐져나와 보이는가"를 사용자가 직접 확인해줬고
("코인밖으로 삐져나온 부분이 있는거같아"), 실제로 버팔로 슬라이드에서 문제를 발견해
수정하는 것이 이번 세션의 목표였다.

## 2. 현재 상태

**확인 완료**:
- 4개 히어로 슬라이드(이글/버팔로/필하모닉/캥거루) 이미지를 직접 열어(`view` 도구,
  확대 크롭) 가장자리를 전수 검사함.
- **버팔로**: 코인 상단(11시~1시 방향)에 원본 사진 속 옛 코인의 어두운 테두리/그림자가
  새로 합성한 디자인 밖으로 튀어나와 보이는 문제를 실제로 확인함. 원인은 GrabCut
  마스크가 실제 코인 윤곽보다 살짝 작게 잡혀, 마스크 바깥 원본 코인의 일부가
  가려지지 않고 남은 것.
- **이글**: 육안으로 크게 티나진 않지만 확대 시 테두리에 미세한 이중선(halo) 아티팩트가
  있었음. 같은 원인으로 판단해 함께 재작업함.
- **필하모닉/캥거루**: 가장자리 전체(360도)를 다시 확인했으나 문제 발견 안 됨 →
  이번 세션에서는 손대지 않음.
- **수정 방법**: 원본 사진(합성 이전 pristine 이미지, git 히스토리에서 복원)에서
  `cv2.grabCut`으로 실제 코인의 정확한 윤곽 마스크를 다시 추출 → 뒤에 서술한 절차로
  타원을 안정적으로 피팅 → 그 타원 크기·위치에 정확히 맞춰 상품 이미지를 리사이즈·색보정
  후 합성. 기존 방식과 달리 "원본 사진에서 뽑은 진짜 코인 윤곽"을 타겟으로 삼았기
  때문에 마스크 밖으로 남는 부분이 구조적으로 없음.
- 수정한 버팔로/이글 이미지를 원본-수정본 비교 이미지로 만들어 `present_files`로
  전달했고, 사용자가 "일단 이대로" 승인함.
- 커밋 `8b08623`으로 `images/header-slide-buffalo.jpg`, `images/header-slide-eagle.jpg`
  교체 후 push 완료. `git ls-remote`로 원격 반영 확인함 (`8b086231e83c...`).

## 3. 진행 단계 (오버행 수정 절차 — 재사용 가능, 캥거루 절차의 개선판)

기존 "캥거루 코인 합성" 핸드오프(`2026-08-*`, 검색 키워드로 찾기)의 절차와 거의
동일하되, **좌표를 눈대중으로 잡지 않고 원본 사진에서 실제 마스크를 추출**하는 것이
핵심 차이다.

1. **원본(pristine) 이미지 확보(필수)**: `git log --follow -- images/header-slide-*.jpg`
   로 해당 파일이 코인 합성되기 이전 커밋을 찾아 `git show <commit>:<path>`로 복원.
   현재 배포본이 아니라 이 pristine 원본을 기준으로 작업해야 이전 합성의 오차가
   누적되지 않는다.
2. **원본 코인의 실제 마스크 추출(필수)**: `cv2.grabCut`을 사용하되, 근처에 돌/나침반
   등 코인과 색이 비슷한 소품이 있으면 일반 사각형 초기화만으로는 소품까지 전경으로
   잡히는 문제가 생김(이글에서 실제 발생). 이 경우 `GC_INIT_WITH_MASK`로 코인
   중심부는 `GC_FGD`, 소품이 있는 영역은 명시적으로 `GC_BGD`로 지정해 seed를 준 뒤
   `grabCut` 실행.
3. **타원 피팅 안정화(필수, 신규 발견 사항)**: 코인이 사진에서 거의 정원에 가깝게
   보일 경우(장축/단축 비율이 1에 가까움), `cv2.fitEllipse`가 반환하는 회전각이
   노이즈에 매우 민감해져 실제와 무관한 각도(예: 150도)가 나올 수 있다. 이 각도를
   그대로 써서 회전시키면 **도안이 뒤집혀 보이는 심각한 오류**가 발생함(이번 세션에
   실제로 겪음). 해결: `cv2.convexHull`로 마스크 컨투어를 먼저 안정화한 뒤 다시
   `fitEllipse`를 적용하면 장축/단축이 거의 같아지고, 이 경우 회전각을 신뢰하지 말고
   **0도(회전 없음)로 간주**하고 진행한다. (버팔로처럼 실제로 눈에 띄게 찌그러진
   타원이면 원래 각도를 써도 무방하나, 결과를 반드시 시각적으로 오버레이해서
   확인할 것.)
4. **상품 이미지 알파 컷아웃 + 색보정(필수)**: 기존 절차와 동일 (`low=8, high=40`
   흰배경 제거, 코인 내부 median 색상 샘플링으로 게인 계산, gain 0.75~1.3 클리핑).
5. **리사이즈 + 합성(필수)**: 타원의 폭/높이에 맞춰 비등방(anisotropic) 리사이즈 →
   `GaussianBlur(0.6)`으로 살짝 부드럽게 → 알파에 `GaussianBlur(1.2)` 페더링 →
   원본 pristine 이미지 위에 정확한 타원 위치에 합성.
6. **원본/수정본 비교 이미지 생성 후 `present_files`로 전달(필수)**: 이번에도 이
   과정을 빠뜨리면 사용자가 결과를 볼 수 없다. 크롭 후 확대(1.5~2배)해서 비교하면
   미세한 테두리 문제가 잘 보임.
7. **승인 후 반영(필수)**: 사용자 승인 시 `git sparse-checkout`에 해당
   `images/header-slide-*.jpg` 경로를 추가해야 파일을 덮어쓸 수 있음(기본 sparse-checkout
   설정이 `/images` 전체를 제외하고 있음) → 덮어쓰기 → add → commit → push.

## 5. 참고 사항

- **sparse-checkout 주의**: 기본 클론 명령은 `/images` 전체를 제외하므로, 히어로
  슬라이드 이미지처럼 `images/` 하위 파일을 수정해야 할 때는
  `git sparse-checkout set --no-cone '/*' '!/images' 'images/header-slide-*.jpg'`
  처럼 필요한 파일 패턴을 추가로 지정해야 워킹 디렉토리에 파일이 나타나고
  덮어쓸 수 있다.
- **타원 회전각 불안정 문제**: 코인이 사진에서 거의 정원으로 보이면 `fitEllipse`
  회전각을 곧이곧대로 믿지 말 것. `convexHull` 적용 후에도 장축/단축이 거의
  같다면 회전각은 0으로 처리. 이 문제를 놓치면 코인 도안이 통째로 뒤집혀
  합성되는 심각한 오류가 남(실제로 이번 세션에서 한 번 발생했다가 재작업으로
  바로잡음 — 최종 커밋에는 반영 안 됨, 중간 결과였음).
- **백업 브랜치**: 이번 세션도 이미지 파일 2개 교체(git 히스토리로 되돌리기 쉬움)라
  별도 백업 브랜치는 생성하지 않음. 최신 백업은 여전히 `backup-2026-08-20-1755`.
- **커밋**: `8b08623` (원격 반영 확인: `git ls-remote` 결과 `8b086231e83c...` 일치).
