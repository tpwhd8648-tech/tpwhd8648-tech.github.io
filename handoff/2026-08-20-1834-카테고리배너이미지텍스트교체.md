## 3. 진행 단계 (이번 세션 실제 흐름)

1. 사용자가 "금시세 배너에 금화 사진이 들어가 있다" 지적 → 클래스/이미지
   불일치 확인
2. 사용자가 은화(브리타니아) 사진 업로드 → 배경 제거·크롭·리사이즈 →
   커밋·푸시(`6f4bf4e`)
3. 사용자가 "문의 배너를 이글코인으로 바꾸고 싶다" 요청 → 원본(앞면)
   다운로드·가공 → 적용
4. 사용자에게 "앞면이야 뒷면이야?" 질문 받고 앞면임을 설명 →
   사용자가 뒷면이 더 낫다고 판단 → 뒷면 재가공·교체 → 커밋·푸시(`1ba7900`)
   (이 사이 GitHub Actions 봇의 자동 커밋 `d882761`이 있어 `git rebase
   origin/main` 후 push)
5. 사용자가 "금화 구매하기 텍스트를 바꾸는 건 어떨까" 제안 → Claude가 3개
   배너 전체를 비교 검토해 의견 제시(문구 불일치·톤 통일 이슈) →
   "금화 보기" vs "전체보기" 논의 → "전체보기"로 결정 → "시세 확인"
   띄어쓰기 정오 확인(명사+명사라 맞음, 그대로 유지 결정) → 반영·
   커밋·푸시(`113654b`) (이 사이 또 Actions 봇 자동 커밋 `481bfca` 있어
   재차 rebase 후 push)

## 5. 참고 사항

- **이미지 가공 방식 정립됨**: 흰 배경 코인 사진 → (1) 흰색 근접 픽셀을
  코너부터 flood-fill로 투명화 → (2) 연결 성분(connected component) 분석해
  가장 큰 덩어리(주 피사체)만 남기고 나머지(잔상·노이즈) 제거 →
  (3) bounding box로 크롭 → (4) 440×440 정사각 캔버스에 98% 크기로
  중앙 배치. 이 파이프라인은 재사용 가능하며, `scipy.ndimage.label` +
  PIL만으로 처리(추가 패키지 설치 불필요).
- **원본 상품 이미지 접근법**: `images/` 폴더는 sparse-checkout에서 제외되어
  로컬에 없지만, `raw.githubusercontent.com/{owner}/{repo}/main/{path}`로
  직접 다운로드 가능함을 확인. `curl`로 받아서 가공하면 됨.
- **Actions 봇 커밋과의 충돌 패턴 재확인**: 이번 세션에서 push 시도 2회
  모두 그 사이 `generate-coin-pages.yml` 워크플로우의 자동 커밋이 먼저
  올라와 있었음. `git fetch` → `git commit`(로컬 변경) → `git rebase
  origin/main` → push 순서로 매번 정상 처리됨. 이 패턴이 반복되는 걸 보면
  앞으로도 push 전 fetch는 필수로 유지할 것.
- **백업 브랜치**: 이번 세션 생성하지 않음 — 전부 이미지 1개 교체 또는
  텍스트 1줄 수정 수준의 저위험 변경이라 판단. 가장 최근 백업은
  `backup-2026-08-03-1829`(기준 커밋 `d0821c0`).
- **PAT 토큰**: 이번 세션 2회 push 모두 채팅에 붙여넣어주신 동일 토큰
  사용, 매번 push 직후 origin URL을 plain HTTPS로 원복. 토큰 값은
  응답에 노출하지 않았고 메모리/파일/로그에 저장하지 않음.
