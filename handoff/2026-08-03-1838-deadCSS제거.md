## 2. 현재 상태

### (1) 제거 전 진단 (확인 완료 — grep으로 CSS 규칙 존재 여부 직접 확인)

- `assets/css/style.css` 전체를 확인한 결과 `.card-price`, `.products-section`에
  대한 스타일 규칙이 존재하지 않음
- 실제 스타일은 함께 붙어있던 `.product-price`(가격 텍스트), `.section`(공통
  섹션 레이아웃)이 담당하고 있었고, `card-price`/`products-section`은 아무
  효과 없이 얹혀만 있는 상태였음
- JS 셀렉터(`querySelector`, `classList` 등)로도 참조되지 않음을 grep으로
  확인 — 순수 마크업 잔재, 제거 시 화면 변화 없음

### (2) 제거 작업 (확인 완료 — 코드 수정 + 검증)

- **`card-price`**: `class="product-price card-price"` → `class="product-price"`
  총 24개 파일에서 제거
  - `index.html`, `pages/coins.html`, `coin-detail.html`, `coins/coin-*.html`
    20개, `assets/js/products.js`, `scripts/generate-coin-pages.js`
- **`products-section`**: `class="section products-section"` →
  `class="section"` — `index.html` 1곳
- **`generate-coin-pages.js` 템플릿 자체를 수정**했으므로, 다음 Actions 실행
  시 이 클래스가 되살아나지 않음 (cache-busting 도입 시 겪었던 "템플릿
  안 고치면 덮어써지는" 문제 재발 방지)

### (3) 검증 (확인 완료)

- 전체 재검색 결과 `card-price`, `products-section` 잔존 0건
- `node --check`로 `products.js`, `generate-coin-pages.js` 문법 통과
- `products.js` 내용이 바뀌면서 cache-busting 해시가 자동 재계산됨
  (`?v=1ed76f82`로 갱신) → 이를 참조하는 22개 HTML도 함께 자동 갱신됨.
  cache-busting 자동화가 "에셋 내용이 바뀌면 관련 HTML만 정확히 갱신"하는
  설계대로 이번에도 정확히 작동함을 재확인
- `inject-cache-busting.js` 재실행 → 0개 갱신 (멱등성 재확인)
- `?v=` 중복 0건

### (4) 원인 추적 (참고용, 코드 변경과 무관)

git 히스토리(`git log -S`)로 두 클래스의 유래를 조사함:

- **`products-section`**: 2026-05-29 최초 커밋(Claude 세션 이전, 수작업
  업로드 시기)에 `.products-section { background: var(--bg-dark); }`라는

  과정에서 CSS 규칙만 사라지고 HTML의 class 이름은 정리가 안 된 채 남은
  것으로 추정
- **`card-price`**: 전체 히스토리를 뒤져도 CSS 규칙이 존재한 적이 없음.

6. git 히스토리 조사로 두 클래스의 유래 확인 (코드 변경 없음, 정보 제공용)
