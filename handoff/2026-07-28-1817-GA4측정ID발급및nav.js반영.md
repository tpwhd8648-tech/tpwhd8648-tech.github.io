- **PAT 토큰 사용**: 사용자가 채팅에 붙여넣은 토큰(`github_pat_11CFWN...`)으로
  1회 push(`db47ecc`) 진행. 토큰 값은 응답에 노출하지 않았고 메모리/파일에
  저장하지 않음.
- **커밋**: `db47ecc` — "feat: GA4 측정 ID(G-2T60WHRDLX) gtag.js 스니펫
  nav.js에 추가". push 전 원격에 다른 자동 커밋(`f148983`, 코인 페이지
  재생성)이 있어 `git pull --rebase` 후 정상 병합·push, `git ls-remote`로
  원격 반영 확인 완료.
- **GA4 스니펫 삽입 위치의 트레이드오프**: `nav.js`가 `</head>`가 아니라
  `</body>` 직전에 로드되는 구조라(30개 페이지 전부 동일), GA 스크립트도
  페이지 로드 후반부에 실행됨. 방문자 추적 자체는 정상 작동하지만, 페이지
  로드 초반에 바로 이탈하는 방문자는 일부 안 잡힐 수 있음. `<head>`에 직접
  넣으려면 27개 HTML 파일 전체를 수정해야 해서 이번엔 nav.js 방식으로
  진행 — 나중에 이탈률 측정이 중요해지면 재검토 여지 있음.
- **캐시버스팅 쿼리스트링(`?v=20260722-2`) 관련 — 오판 정정 기록**: nav.js
  수정 직후 "쿼리스트링을 안 올려서 캐시된 옛 버전이 계속 쓰일 수 있다"고
  [영향 높음]으로 잘못 판단했었음. 실제로는 GitHub Pages가 `Cache-Control:
  max-age=600`(10분)만 설정하므로 최악의 경우도 10분 내 자동 해소되는
  낮은 리스크였음 — 웹서치로 재확인 후 [영향 낮음]으로 정정함. **다음에
  캐시 관련 영향도 판단할 때는 실제 서버가 어떤 Cache-Control을 쓰는지
  먼저 확인하고 판단할 것** (GitHub Pages는 기본 10분 캐시).
