## 2. 현재 상태

### 2-1. 가격 배율 +1.5% (완료, 확인 완료)

- 사용자가 "모든 상품 1.5퍼센트 인상"을 요청했고, 배율(5번째 열)에 ×1.015를 곱해 소수 넷째 자리로 반올림한 23행 전체를 복붙용으로 제공했다. 사용자는 "더하기(+0.015)와 곱하기 차이"를 물은 뒤 곱하기를 그대로 썼다. 곱하기가 더하기보다 배율이 약 0.0019~0.0023 높다.
- 사용자가 시트에 붙여넣은 내용을 두 번 검증했다(23행 전부 ×1.015 결과와 일치, 나머지 열 불변). 시트가 끝자리 0을 지운 행(캥거루 1.146, 1.145)은 값이 같다.
- Actions 수동 실행(workflow_dispatch)을 이번 세션에 4회 돌렸고 모두 `generate` 작업 성공. 결과를 `git fetch`로 받아 확인했다: `coins/coin-*.html` 23개, `pages/coins.html` 카드 23개 전부 `data-category="gold"`, sitemap에 코인 URL 23개.
- **가격 검증 방법**: Actions 로그의 `krwPerOz = 5,175,542.981원/oz`(시세 변경 후 실행)로 `round(krwPerOz × 배율 / 1000) × 1000`을 직접 계산해 생성된 `"price"`와 비교했다. 8개 상품을 확인해 7개가 일치했다(양띠 6,048,000, 2027 브리타니아 5,942,000, 2027 캥거루 5,931,000, 2026 메이플 5,967,000, 2026 브리타니아 5,935,000, 2026 캥거루 5,926,000, 레이디저스티스 5,995,000원).
- **판다만 불일치**: 페이지 가격 5,859,000원, 배율 1.1521로 계산하면 5,963,000원. 역산하면 시트의 판다 배율이 약 1.132(5,859,000 ÷ 5,175,543)로 바뀐 것으로 보인다. 시트는 직접 읽을 수 없어 역산값이며 사용자의 의도 변경인지는 **확인하지 않았다.**
- **판다 category 사고**: 이번 세션에서 Claude가 판다 행을 `gold_30g`로 바꾸라고 안내했으나, 코드(`generate-coin-pages.js`와 `products.js`의 `getCategoryFilter`)는 `gold_1oz`/`gold`만 금화로 인식해서 `data-category="gold_30g"`가 되어 "금화" 필터에서 빠질 상태였다. Claude가 추측으로 만든 값이었다. 사용자가 시트를 `gold_1oz`로 되돌렸고 재실행으로 23개 전부 `gold`임을 확인했다.
- **중량 미반영**: 가격식이 `krwPerOz × premium`이라 중량(30g)이 반영되지 않는다. 판다(30g)는 1oz 코인과 같은 방식으로 계산된다. 의도 여부는 **미확인**.

## 5. 참고 사항

**작업 방식에서 확인된 것**
- Actions 실행: `gh api -X POST repos/tpwhd8648-tech/tpwhd8648-tech.github.io/actions/workflows/generate-coin-pages.yml/dispatches -f ref=main`을 `add_repo`(access: push) 이후에 호출해 성공했다. 실행 로그에서 `krwPerOz` 줄로 그 시점의 환산 시세를 확인할 수 있다. 완료는 `gh run watch <id> --exit-status`로 기다렸다.
- 구글 시트의 `gviz` 주소는 이 세션에서 WebFetch가 허용되지 않아 직접 읽지 못했다. 시트 값은 Actions 결과(생성된 `price`, `data-premium`, `data-category`)로 역산해 확인했다.
- 푸시 전에 항상 `git fetch --depth=1 origin main`으로 원격이 움직였는지 확인했고, 이번 세션 푸시 3건 모두 내 커밋의 부모가 원격 최신과 같아 충돌 없이 올렸다. 푸시 후 봇 커밋이 얹히므로 로컬은 `git reset --hard origin/main`으로 맞췄다.
- 세션 종료 훅이 "커밋하고 푸시하라"고 여러 번 알렸으나, 프로젝트 지침(섹션 3)에 따라 사용자의 "푸쉬해줘" 확인이 있을 때만 푸시했다.

**의사결정의 이유**
- 곱하기 인상: 사용자는 "1.5% 인상"을 그대로 판매가 1.5% 상승으로 쓰려고 곱하기를 택했다. 더하기는 판매가 상승이 약 1.30~1.33%에 그친다.
- 번호 표기: "문자 문의" 문구 대신 번호만 쓰고 말풍선 아이콘만 둔 것은 사용자 결정이다. 법적 표시 칸(사업자 정보)은 "전화번호"로 적었다. 전자상거래 사업자 정보에 전화번호 표시가 필요한 것으로 Claude가 알고 있으나 **법률 확인은 하지 않았다.**
- 24시간 삭제: 밤 문의에 즉시 답하지 못할 때 고객 기대와 어긋나는 것을 막으려는 취지로 사용자가 결정했다. Claude는 "접수는 24시간, 답변은 영업시간" 통일안을 추천했으나 사용자는 삭제를 택했다.

**사실로 확인하지 않은 것**
- 시트의 현재 값(특히 판다 배율), 이번 변경의 모바일·태블릿 렌더링, 말풍선 아이콘의 실제 모양.
- TradingView 위젯 자체에 출처 표시가 있는지, 이용약관상 별도 표기가 필요한지.
- 사업자 정보 전화번호 표시 의무의 정확한 범위.

**공개 범위 주의**
