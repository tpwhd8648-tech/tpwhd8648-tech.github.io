# 카톡 링크 교체 및 카톡방 시세 자동 발송 시험 인수인계 문서

작성일: 2026-11-23 (KST 16:05)

> **다음 세션 Claude에게**: 이 문서의 4번 To-Do는 직전 인수인계(2026-11-17-1730)의 이월 항목 전체에 이번 세션의 신규 항목을 더한 것이다. 11-17 문서가 이미 2026-11-06-0103, 2026-10-17-1727 문서를 교차 확인해 이월했고, 이번에는 11-17 문서를 기준으로 삼았다. 이번 세션에서 종결한 항목은 없어서 이월 항목은 그대로 남겼다. 푸시는 사용자가 "푸쉬해줘"라고 말할 때만 한다.

## 1. 목표

(1) 카톡 오픈채팅 링크를 새 주소로 바꿔 손님이 익명 오픈프로필로 문의할 수 있게 한다. (2) 시세 공지를 카톡방에 매일 정해진 시각에 올리는 작업을 간편하게 하거나 자동화할 수 있는지 시험한다.

## 2. 현재 상태

### 2-1. 카톡 링크 교체 (푸시 완료, 확인 완료)

- 사용자가 새 오픈채팅 링크 `https://open.kakao.com/o/syk7MkYi`를 주고 교체를 요청했다. 29개 파일, 30군데를 교체했고 커밋 `27baad8`(`12b07d4..27baad8`)로 푸시했다. 대상은 `footer.js`(플로팅 버튼·푸터 아이콘), `inquiry.js`, `coin-detail.html`, `coins/` 코인 페이지, `contact.html`, `mypage.html`, `scripts/generate-coin-pages.js`다. 생성 스크립트도 바꿔서 Actions가 돌아도 옛 링크로 돌아가지 않는다.
- 옛 링크 `sB6Gduni`는 `handoff/` 과거 문서에만 남겼다(과거 기록이라 의도적으로 둠).
- 이번 세션에서 `git fetch`와 `git log`로 원격 최신(`4c517cc`)을 확인했다. 푸시 후 Actions가 성공했고 캐시 해시도 갱신됐다고 이전 세션 기록에 있다(이전 세션 대화 기록 기준, 이번 세션에서 해시값은 다시 확인하지 않았다).
- **미확인**: 새 링크가 1:1 방인지, "기본프로필로만 참여 허용"이 꺼져 있어 손님이 익명 프로필로 들어올 수 있는지. 카카오 페이지는 자동 접근이 막혀 Claude가 열지 못했다.

### 2-2. 시세 갱신 구조 (확인 완료, 이전 세션 코드 점검 기준)

- 방문자가 사이트를 열어 둔 동안 브라우저가 구글시트 "계산" 탭을 30초마다 읽는다(`assets/js/nav.js`). 정적 코인 페이지는 하루 1번 자정(KST) 빌드와 푸시 때 갱신된다.
- 시트 값이 실제로 얼마나 자주 바뀌는지는 시트를 읽지 못해 **확인하지 않았다.**

### 2-3. 카톡방 시세 자동 발송 시험 (진행 중, 일부만 확인)

- 사용자가 사이트 배너는 필요 없다고 했고, 카톡방에 매일 주기적으로 올리는 것을 간편하게 하거나 자동화하길 원한다. 오픈채팅방에 자동 발송하는 공식 기능은 찾지 못했고(카카오 개발자 포럼 답변 기준) 비공식 봇을 시험하기로 했다.
- 서브폰(안드로이드)에 메신저봇을 설치하고 시험 계정으로 로그인했다. 봇 "시험봇"을 만들었다(레거시 API 체크 기본값).
- **확인 완료(사용자 보고)**: 본계정으로 시험 방에 `시험`을 입력하면 봇이 즉시 답장하고, 10초 뒤 "테스트 메시지입니다"가 한 번 왔다. 처음엔 반응이 없다가 설정을 바꾸지 않았는데 두 번째에 작동했고 원인은 모른다.
- **미확인**: 몇 시간 이상 뒤의 정해진 시각 발송, 화면이 꺼진 상태에서의 동작, 며칠 연속 발송, 중복 발송 여부, 카카오의 제재 위험.
- 마지막으로 Claude가 드린 코드는 09·11·13·15·17시에 구글시트 "계산" 탭(1행: A=금, B=은, C=백금, E=환율로 가정)의 시세를 `[시세 안내] 날짜 시각 / 금·은·백금 $ / 환율 원` 형태로 방에 보낸다. `시세시험` 입력 시 즉시 시세 메시지를 보내고, `시험` 입력 시 그 방을 발송 대상으로 등록한다. 문법 검사와 가짜 값 점검만 했고 **실제 시트 조회는 사용자 서브폰에서 시험된 적이 없다.** 사용자가 이 코드를 앱에 붙여 실행했는지도 확인하지 못했다.
- 이 코드는 시트 ID가 들어 있어 공개 레포의 이 문서에는 넣지 않았다. 필요하면 Claude가 다시 만들어 준다.

### 2-4. 푸시와 접근 권한

- 이번 세션에서는 이 문서 커밋까지 로컬에 만든다. 푸시는 사용자 "푸쉬해줘" 확인 후에만 한다. 토큰은 저장하지 않았고 이 문서에도 적지 않았다.

## 3. 진행 단계

### 필수 (1순위)

1. 푸시된 사이트에서 새 카톡 링크가 모든 버튼에서 새 방으로 열리는지 시크릿 창으로 확인한다.
2. 새 링크의 방이 1:1 방인지, 다른 계정으로 열었을 때 오픈프로필 선택이 되는지 확인한다.
3. 서브폰에서 `시세시험` → `시험` 순서로 시세 조회와 방 등록이 되는지 확인한다.

### 선택 (나중에 해도 무방)

5. 공지용 다대일 방(그룹/커뮤니티/Lite)을 만들지 정한다.

## 5. 참고 사항

- **의사결정의 이유**: 거래 문의는 손님끼리 대화가 보이지 않는 1:1 방이 맞고, 시세 공지는 별도 방이 맞다는 것이 Claude의 안내였다. 자동 발송은 모두 비공식이라 폰 상태·카톡 업데이트에 따라 끊길 수 있으므로, 중요한 공지는 수동 대체(복사 페이지)를 같이 두라고 안내했다.
- **자동 발송 주의**: 사장님 본계정이 아닌 시험 계정, 손님이 없는 시험 방에서만 한다. 컴파일을 여러 번 누르면 중복 발송 사례가 있다. 서브폰은 충전기·와이파이·절전 제외 상태를 유지해야 하고, 본계정이 보낸 메시지여야 서브폰에 알림이 온다.
- **사실로 확인하지 않은 것**: 새 링크의 방 유형·프로필 설정, 시트의 시세 갱신 속도, 봇 코드의 실제 시세 조회, 카카오 운영정책상의 자동 발송 허용 여부.
- **이전 세션 내용의 출처**: 2-1의 해시 갱신, 2-2의 코드 점검, 2-3의 사용자 시험 결과는 이전 세션 공유 기록(사용자가 붙여넣음)에 근거한다. 이번 세션에서 Claude가 직접 다시 확인한 것은 원격 커밋 기록과 11-17 핸드오프 내용이다.
- **백업 브랜치**: 이번 세션에서는 만들지 않았다. 링크 교체는 문자열 치환이라 지침 3-1의 기준에 해당하지 않는다고 판단했다. 링크 교체 롤백 기준은 `27baad8`의 부모 `12b07d4`다.
- **공개 범위 주의**: 이 문서는 `handoff/`에 있어 GitHub Pages로 누구나 열 수 있다. 토큰·시트 ID 등은 적지 않았다.
