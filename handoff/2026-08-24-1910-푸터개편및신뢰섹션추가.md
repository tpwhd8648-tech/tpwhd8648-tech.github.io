# 푸터 개편 및 신뢰(왜 원트로이 불리온인가) 섹션 추가 인수인계 문서

작성일: 2026-08-24 19:10 (KST)

## 1. 목표

푸터의 상호 표기·사업자 정보 노출 방식을 개편하고, WOWPASS류 카드형
안내 디자인을 참고한 "왜 원트로이 불리온인가 / 이용 방법" 신뢰 섹션을
about.html → index.html 순으로 확대 배치하는 작업. 사용자가 다음
세션에서 세 번째 페이지에도 이 섹션을 추가할 예정.

## 2. 현재 상태 (모두 완료, 배포됨 — 확인 완료)

### (1) 푸터(footer.js) 개편 — 완료
- 상호 표기 순서: "골든민트(ONETROY BULLION...)" → "원트로이 불리온
  (ONETROY BULLION / 골든민트)"로 변경. 상호 변경 신고 미완료 상태라
  법적 표시 상호(골든민트)는 유지하되 노출 순서만 반전, "등록상호:"
  라벨은 제거하고 텍스트만 남김.
- 대표자명·사업자등록번호·주소·전화번호를 "사업자 정보 보기" 클릭형
  아코디언으로 전환. 상호/저작권 문구만 항상 노출.
- 전화번호(오시는 길 섹션 + 아코디언 상세) 두 곳 모두 "(임시)" 표기 추가.
- "귀금속은 투자 위험이 있습니다..." 고지 문구 삭제.

### (2) 사업자 정보 노출 현황 — 확인 완료 (grep 전수 검색)
실제 사업자등록번호·주소·전화번호가 화면에 노출되는 곳은
**모든 페이지 공통 footer.js의 아코디언 1곳뿐**. about.html은 이번
세션에 중복 블록을 삭제했고, terms.html은 항목명만 언급할 뿐 실제
숫자는 없음.

### (3) "왜 원트로이 불리온인가 / 이용 방법" 섹션 — about.html, index.html 완료
- WOWPASS 카드형 디자인 참고, 문구는 실제 사업 내용에 맞게 재작성함
  (금융감독원 인가·보증보험 등 환전업 관련 문구는 사용하지 않음).
- 카드 4개: 합리적인 가격 / 간편한 문의 / 직접 확인 후 거래 / 정품만 취급
- 스텝 3개: 01 카카오톡 문의 → 02 가격·장소 협의 → 03 만나서 거래
- 배치 순서: about.html에 우선 배치(가장 노출 적은 페이지, 반응 테스트
  목적) → 사용자가 반응 보고 index.html 맨 아래(브랜드 섹션~푸터 사이)
  로 확대 결정 → 적용 완료. about.html 버전은 삭제하지 않고 그대로 유지.
- **CSS는 style.css에 공용 정의**(`.why-steps-section`, `.why-grid`,
  `.why-card`, `.steps-grid`, `.step-card` 등)해서 index.html이 참조.
  단 about.html은 원래 자체 inline `<style>` 블록에도 같은 클래스를
  중복 정의해 놓은 상태(충돌은 없음, 값 동일).
- **⚠️ 텍스트는 자동 동기화 안 됨**: about.html과 index.html 두 곳에
  카드/스텝 문구가 각각 하드코딩되어 있음. 이번 세션에 양쪽 파일에
  "수정 시 다른 파일도 같이 고칠 것"이라는 안내 주석을 추가해둠
  (`pages/about.html`의 `<div class="why-section">` 바로 위 주석,
  `index.html`의 `<section class="why-steps-section">` 바로 위 주석).

## 5. 참고 사항

- **텍스트 중복 구조의 근본 원인**: 이 사이트는 컴포넌트/템플릿 시스템
  없는 순수 정적 HTML이라, 동일 문구를 여러 페이지에 쓰려면 하드코딩
  복사만 가능함. footer.js/nav.js처럼 JS로 공통 삽입하는 방식도 있지만,
  이 신뢰 섹션은 about.html에서는 페이지 본문 흐름 중간에, index.html
  에서는 다른 위치에 들어가 있어 완전히 동일한 JS 삽입 스니펫으로
  묶기엔 배치 컨텍스트가 다름. 페이지가 3개 이상으로 늘어나 관리
  부담이 커지면, 차라리 `assets/js/why-section.js` 같은 공용 스크립트로
  분리해서 각 페이지가 `<div id="why-section-mount"></div>`만 두고
  로드하는 방식으로 리팩터링하는 것을 고려할 만함 (아직 미결정, 사용자
  판단 필요).
- **CSS는 이미 공용화됨**: 위 텍스트와 달리 스타일(`.why-grid`,
  `.why-card` 등)은 `assets/css/style.css`에 정의돼 있어 사이트 전체가
  공유함. 디자인(색상/여백/폰트 등)을 바꿀 때는 style.css 한 곳만
  고치면 모든 페이지에 반영됨 — 단, about.html 자체 inline `<style>`에
  중복 정의된 부분은 예외이므로 함께 확인 필요.
- **백업 브랜치**: 이번 세션 생성하지 않음 — 텍스트/CSS 추가 위주라
  되돌리기 쉬운 변경으로 판단. 가장 최근 백업은
  `backup-2026-08-03-1829`(기준 커밋 `d0821c0`).
