# 도메인 이전 sitemap 재제출 및 검색엔진 소유확인 인수인계 문서

작성일: 2026-09-14

## 1. 목표

직전 세션(`2026-09-14-1916`)에서 도메인 전면 교체(`tpwhd8648-tech.github.io` →
`onetroy.co.kr`) 및 내부 링크 `.html` 확장자 제거 작업이 완료되면서, 검색엔진이
알고 있던 예전 URL 체계가 전부 바뀌었다. 이번 세션에서는 그 후속 조치로 구글
서치콘솔·네이버 서치어드바이저에 새 도메인을 등록하고 sitemap을 재제출해,
검색엔진이 새 URL을 최대한 빨리 재인식하도록 한다.

## 2. 현재 상태

### 확인 완료

- **리디렉션 확인**: 사용자가 직접 브라우저에서 구 도메인
  (`tpwhd8648-tech.github.io/index.html`) 접속 → 자동으로 `onetroy.co.kr`로
  이동됨을 스크린샷으로 확인. GitHub Pages 커스텀 도메인 설정 시 기본
  제공되는 301 리디렉션이 정상 동작 중.
- **구글 서치콘솔**:
  - `onetroy.co.kr` 속성을 URL 접두어 방식으로 신규 등록, HTML 파일
    업로드 방식으로 소유확인 완료 (레포 루트에 `google8567eddb7a74f3b8.html`
    추가 → 커밋 `b01f3b2` → 푸시 완료, 소유권 자동 확인됨을 스크린샷으로 확인).

  - "주소 변경(Change of Address)" 도구로 구→신 도메인 이전 신고 완료 —
    유효성 검사 통과(301 리디렉션 확인됨, 두 사이트 모두 소유 확인됨) →
    "이동 확인" 처리.
- **네이버 서치어드바이저**:
  - `onetroy.co.kr` 신규 등록, HTML 파일 업로드 방식으로 소유확인 완료

  - `sitemap.xml` 제출 완료 — 등록 확인됨.
  - 핵심 페이지 8건 수동 웹페이지 수집 요청 완료: `/`, `/pages/coins`,
    `/coins/coin-kangaroo-2026`, `/coins/coin-maple-2026`,
    `/coins/coin-eagle-2026`, `/pages/about`, `/pages/gold-price`,
    `/pages/faq` (모두 확장자 없는 sitemap 기준 정식 URL 형태로 제출).
  - 참고: 레포에 예전부터 있던 네이버 인증 파일

## 3. 진행 단계 (재사용 가능 메모)

- **도메인 전면 교체 후 검색엔진 후속 조치 순서**: (1) 구 도메인에서
  신 도메인으로 301 리디렉션이 실제로 걸려 있는지 먼저 확인 → (2) 걸려
  있으면 구글 서치콘솔은 "주소 변경" 도구 사용(sitemap 재제출과 별개로
  진행), 안 걸려 있으면 sitemap 재제출만 진행 → (3) 신 도메인 속성/사이트
  등록 시 HTML 파일 업로드 방식이 GitHub Pages와 가장 간단(레포 루트에
  파일 추가 후 푸시만 하면 됨, DNS 접근 불필요) → (4) sitemap 제출 →
  (5) 핵심 페이지만 선별해 수동 수집 요청(전체 페이지 다 넣을 필요 없음,
  나머지는 sitemap으로 자연스럽게 크롤링됨).
- **수동 수집 요청 페이지 선별 기준**: 메인 → 전체 상품 목록 페이지 →
  대표 상품 상세 2~3개 → 회사소개/시세정보/FAQ 등 신뢰도·정보성 페이지.
  개별 상품 상세 페이지를 전부 넣을 필요는 없음(sitemap이 처리).
  연도가 붙은 상품 페이지(`coin-eagle-2026` 등)는 내년 신제품 교체 시
  URL이 바뀔 수 있지만, 수동 수집 요청은 일회성 크롤링 요청일 뿐이라
  당장의 검색엔진 등록과는 무관함 — 그래도 신경 쓰이면 연도 무관한
  고정 페이지(`pages/gold-price` 등)로 대체 가능.
- **검증 파일 접근 제약**: Claude의 bash 네트워크 정책상 `onetroy.co.kr`
  도메인에 직접 접근(curl/fetch) 불가 — 사용자가 브라우저로 직접 접속해
  캡처를 공유하는 방식으로 확인을 진행함. `web_fetch` 도구도 사전
  검색/대화에 나온 적 없는 URL은 열 수 없어 동일한 제약이 있음.
