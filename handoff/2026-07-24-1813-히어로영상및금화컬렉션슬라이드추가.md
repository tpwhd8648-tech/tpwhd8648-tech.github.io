작성일: 2026-07-24 (KST)

## 1. 목표

직전 핸드오프(`2026-07-24-1654-히어로배너디자인개편1차.md`)에서 진행 중이던
"히어로 영상 슬라이드 추가"(🔴 우선순위)를 마무리함. 사용자가 Pexels에서 받은
브랜드 소개용 영상 1개를 5번째 슬라이드로 추가하고, 이어서 Pexels에서 찾은
금화 컬렉션 사진 5장을 추가 슬라이드로 넣었다가, 최종적으로 하나의 슬라이드
안에서 배경이 자동 순환되는 형태로 재구성함.

## 2. 현재 상태

### (1) 히어로 영상 슬라이드 추가 (반영 완료 — 커밋 `d2af4f7`, push 완료)

- 대상 파일: `index.html`(`heroSlides` 배열, `renderHeroSlides` 함수),
  `assets/css/style.css`
- 사용자가 Pexels에서 다운로드한 영상(`8733007-hd_1920_1080_30fps.mp4`,
  12초, 1920x1080, 오디오 없음)을 `videos/hero-intro.mp4`로 저장
- `heroSlides` 배열에 `video` 필드 지원 추가 — `video`가 있으면 `<video
  autoplay muted loop playsinline>` 배경 + 어두운 오버레이가 `image` 대신
  렌더링됨
- 신규 1번 슬라이드: 배지 "ONETROY BULLION", 제목 "투자의 시작 / 원트로이
  불리온", 버튼 "전체 상품 보기 ›" → `pages/coins.html`
- 기존 이글/버팔로/캥거루/필하모닉 4개 슬라이드는 순서만 뒤로 밀림, 내용 동일
- CSS: `.slide-video-bg`, `.slide-video-overlay` 클래스 추가
- 검증: `node -c`로 스크립트 블록 전체 문법 확인, raw.githubusercontent.com
  으로 원격 반영 확인 완료
- 이후 사용자 요청으로 1번 슬라이드 **부제(subtitle) 제거** (커밋 `7bbb567`,
  push 완료) — `renderHeroSlides`도 함께 수정해 subtitle이 없으면 `<p>`
  태그 자체가 렌더링 안 되도록 처리(`undefined` 노출 방지)

### (2) 조폐국 공식 영상/이미지 재사용 가능 여부 조사 (코드 변경 없음, 정보 제공만)

- 사용자가 "유튜브에 각 국가 민트가 올려놓은 영상을 써도 되는지" 질문 →
  YouTube 자체 정책상 다운로드 재업로드 금지, 미국 조폐국은 자체 이용약관에
  상업적 재사용 시 사전 서면 허가 필요 명시(확인 완료 —
  usmint.gov/resources/terms-of-use), 퍼스 민트·오스트리아 조폐국은 크라운
  저작권 등으로 자동 자유이용 아님을 설명함
- 미국 조폐국의 공식 미디어킷(`usmint.gov/news/media-kit`)에 보도용 영상이
  존재하나 "언론 보도용" 명목이라 온라인 쇼핑몰 마케팅 배경으로 쓰기엔
  회색지대라고 안내, 실제 사용하려면 라이선싱 부서(licensing@usmint.treas.gov)
  직접 문의를 권장함 — **사용자가 아직 문의하지 않은 상태**

### (4) 금화 컬렉션 사진 5장 → 슬라이드 반영 (반영 완료 — 커밋 `a017ab5`,

- 1차: 5장을 각각 별도 슬라이드(2~6번)로 추가 → 총 10개 슬라이드가 됨
- 2차(사용자 요청): "이미지들을 한 슬라이드에 넣고 싶다" → 두 가지 방식
  (콜라주 합성 vs 미니 캐러셀형 자동 순환) 중 **미니 캐러셀형**으로 확정

- 배지/제목/부제/버튼은 슬라이드당 1세트로 고정 — 배지 "WORLD MINT

  보기 ›" → `pages/coins.html`

  overlay`와 동일 오버레이 스타일 공유) 추가

## 5. 참고 사항

- **백업 브랜치**: `backup-2026-07-24-1722` (영상 슬라이드 추가 직전,
  `index.html` + `style.css` + 신규 영상 파일 등 다중 파일 변경 전 생성).
  이후 이미지 저장 커밋들과 부제 제거, 슬라이드 통합 작업은 각각 파일 1~2개
  수준의 변경이라 추가 백업 브랜치는 생성하지 않음.
- **PAT 토큰 사용**: 이번 세션에서 사용자가 채팅에 붙여넣은 토큰
  (`github_pat_11CFWN...`)을 재사용해 총 8회 push 진행(영상 슬라이드, 이미지
  5장 개별 저장, 부제 제거, 슬라이드 통합). 토큰 값은 응답에 노출하지 않았고
  메모리/파일에 저장하지 않음.
- **git sparse-checkout과 이미지 파일**: 레포는 `images/` 폴더를 sparse-
  checkout에서 제외한 상태로 클론하므로, `images/` 밑에 파일을 추가할 때는
  `git add`가 아니라 `git add --sparse <path>`를 써야 함(안 그러면 "매칭은
  되지만 sparse-checkout 정의 밖" 경고와 함께 추가 안 됨). 이번 세션에서
  5회 반복 확인된 패턴이니 다음에도 참고.
- **`heroSlides`에 3가지 배경 타입 공존**: `image`(단일 정지 이미지),
  `video`(단일 영상), `images`(배열, 자동 순환) 세 가지가 `renderHeroSlides`
  안에서 분기 처리됨. 새로운 슬라이드 타입을 추가할 때는 이 세 분기
  (`bgStyle`/`videoBg`/`cycleBg` 변수와 `slideClass` 조건문)를 모두 확인할 것.
- **`images` 배열 순환 애니메이션의 키프레임은 슬라이드 인덱스별로 동적
  생성**됨(`heroBgCycle{i}`라는 이름으로 `<style id="hero-bg-cycle-style">`
  태그에 주입). 이미지 개수가 바뀌어도 자동으로 노출 시간(`CYCLE_SEC = 4`초
  고정, 총 주기는 `개수 × 4초`)이 재계산되므로, 사진을 추가/삭제할 때는
  `heroSlides`의 `images` 배열만 수정하면 됨(별도 CSS 수정 불필요).
- **Pexels 사진 라이선스 관련 설명**: 사용자가 "이 사진들 다 무료로 써도
  되냐"고 반복 질문함 — Pexels는 저작자 표시 불필요·상업적 이용 가능한
  포괄적 사전 라이선스 구조라고 설명함. 다음에 비슷한 질문이 나오면 이
  핸드오프의 설명(작가가 Pexels와 사전 계약, 개별 이용자와 재계약 불필요)을
  재사용 가능.
- **조폐국 공식 자료 재사용은 여전히 회색지대**: 이번 세션은 조사만 했고
  실제 문의는 안 한 상태. 만약 사용자가 나중에 "조폐국에서 답장 받았다"고
