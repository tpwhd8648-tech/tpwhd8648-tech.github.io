뒤 최종 결정을 내려 종결 처리함. 아울러 직전 세션(`2026-07-30-1019`)에서 넘어온

배포 사이트 접근이 불가능한 이 작업 환경 제약 안에서 가능한 최대한(코드 레벨
시뮬레이션)으로 검증하여 종결 처리함. 코드 변경은 없음(검토·검증만 수행).

## 2. 현재 상태

### (1) "구 미다스 불리온" about.html 언급 여부 (종결)

- 사용자가 네이버 서치어드바이저의 콘텐츠 노출/클릭 현황, 사이트 진단, 검색 키워드
  TOP 30 화면을 캡처해 공유 → 확인 결과:
  - 전체 사이트 노출량 자체가 하루 20~30건 수준으로 표본이 매우 작음
  - "onetroy bullion", "원트로이", "원트로이불리온", "원트로이 불리온" 등 표기가
    조금씩 다른 변형 4개가 TOP 10 안에 몰려있어 자기 검색(본인이 직접 여러 표기로
    검색해본 것) 오염 가능성이 높다고 판단
  - "미다스 불리온" 단일 키워드는 노출 24회로 여전히 1위이나, "원트로이" 계열
    4개를 합산하면 노출 32회로 이미 미다스를 넘어선 상태
- **사용자 최종 결정**: about.html에 "구 미다스 불리온" 언급을 추가하지 않음
- **종결 사유**: 표본 신뢰도가 낮고, 원트로이 계열 합산 노출이 이미 우세하므로
  옛 이름을 다시 노출시킬 실익이 없다고 판단

### (2) coins.html 20개 카드 premium 매칭 로직 검증 (종결 — 단, 아래 한계 있음)

- `refreshPremiumsFromSheet()`의 2차 매칭 로직(`getSlugForProduct`)을 Node.js로
  그대로 재현하고, `assets/js/coin-data.js`의 실제 `IMAGE_MAP`을 로드해서
  `pages/coins.html`에서 추출한 20개 카드명(`.product-name`) 전부를 슬러그로
  변환 시도함 (확인 완료: 코드 재현 + 실행)
  - 결과: 매칭 실패(slug=null) 0건, 중복 slug 0건, IMAGE_MAP 20개 항목과 카드
    20개가 정확히 1:1 대응
  - `scripts/generate-coin-pages.js`도 동일 키워드 세트(`COIN_DESCRIPTIONS.keywords`
    = `IMAGE_MAP.keywords`와 동일)로 시트 `name` 컬럼을 매칭해 이미
    `/coins/coin-*.html` 20개 정적 페이지를 성공적으로 생성한 상태 → 시트의 실제
    상품명도 이 키워드들을 포함하고 있음이 간접적으로 증명됨
  - **결론**: 카드-시트 매칭 로직(1차 실패 시 2차 슬러그 fallback)이 20개 코인
    전부에서 구조적으로 실패할 가능성이 없음을 코드 레벨에서 확인
- **검증 못 한 부분(한계, 확인 안 됨)**: 이 작업 환경은 네트워크 정책상
  `docs.google.com`(구글시트)과 `tpwhd8648-tech.github.io`(실배포 사이트) 모두
  `web_fetch`/`bash` 접근이 차단되어 있어, 실제 브라우저에서 시트 fetch가
  정상 응답하는지, Network/Elements 탭에서 `data-premium` 값이 실제로 갱신되는지는
  이번 세션에서도 여전히 직접 확인하지 못함
- **종결 범위**: "매칭 로직 자체의 실패 가능성" 항목만 종결. "배포된 페이지에서
  실제 premium 갱신이 동작하는지"(브라우저 확인)는 별도 항목으로 계속 남겨둠
  (아래 To-Do 4번 참고)
